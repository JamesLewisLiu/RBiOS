# Display cadence and interpolation

The game logic, judgment windows, score updates and AFP simulation remain at their original 60 Hz. `GameSurface` asks MetalKit for up to 120 display frames per second, bounded by the attached screen's `maximumFramesPerSecond`. Supported iPad Pro displays can therefore show an intermediate note position between completed logic snapshots. Other screens retain their supported rate. System power, thermal and accessibility limits can reduce the actual cadence; a preference does not guarantee 120 fps.

`StageFrameInterpolation` accepts completed snapshots. For exactly consecutive ticks it blends the four corners of stable, matching note sprites over one logic interval. It never advances simulation or predicts future states. This introduces up to one 60 Hz interval (16.7 ms) of visual interpolation delay; judgment and touch timestamps keep using the original audio clock. New/removed notes, texture changes, changed masks or layers, and movements over 128 logical pixels snap to the new state. Batched tick gaps also snap. UI and background sprites retain their discrete original animation states. Duplicate/out-of-order frames do not restart interpolation. When the worker stalls, the renderer holds the latest completed state after the interpolation interval.

Pausing, screen attachment, layout changes and backgrounding clear the interpolation buffer. The controller must also clear it when freezing or resuming its session. No stale note is recreated after a removal.

Static overhead reductions: unchanged normalized warp grids are reused; axis-aligned sprites use no warp grid; cached texture objects are not reassigned unnecessarily. `prepareSessionTextures` creates and preloads supported in-memory textures before gameplay. These target observed allocation/first-use paths in the source; they are not measured proof of the device's occasional stalls.

The test suite checks the 120 Hz midpoint, complete 60 Hz endpoints, stalls, skipped ticks, reset, stale submissions, texture/lifecycle changes, large discontinuities, and screen-limited cadence. Existing offscreen Metal rendering tests continue to exercise the same renderer. Actual M1 iPad frame times and audio/visual alignment require a device run.

Apple references: [UIScreen maximumFramesPerSecond](https://developer.apple.com/documentation/UIKit/UIScreen/maximumFramesPerSecond), [MTKView preferredFramesPerSecond](https://developer.apple.com/documentation/metalkit/mtkview/preferredframespersecond), and [ProMotion guidance](https://developer.apple.com/documentation/quartzcore/optimizing-iphone-and-ipad-apps-to-support-promotion-displays). The implementation uses APIs available on iPadOS 14. The iPhone-specific minimum-frame-duration plist opt-in is not needed for the targeted iPad Pro.
